Research · Episode 1

AI Causal Reasoning
via RAG

The first research ticket raised through DeskOps investigated one of the most contested questions in AI: does it reason causally, or is it a sophisticated pattern-matcher?

Four academic papers were indexed as attachments. The RAG pipeline retrieved relevant chunks, a pre-screening pass filtered them for relevance, and the system generated a structured resolution note with inline citations grounded in the evidence.

Q1 To what extent do current AI agents rely on correlation rather than causal reasoning?
Q2 How can we detect when an agent is using spurious correlations instead of meaningful relationships?
Q3 Are there reliable indicators that distinguish causal reasoning from pattern matching in model outputs?
Q4 How does shortcut learning manifest in multi-step agent workflows?
Cynefin Classification
The resolution framework uses domain classification to calibrate tone — a Clear domain note is direct and factual, while a Complex domain note acknowledges uncertainty and avoids false certainty. The AI reasons through this silently before writing a single word.
Bloom's Taxonomy Depth
Each note is calibrated to the appropriate cognitive level — from recalling a known fix through to synthesising a novel approach from first principles. The depth of the output reflects the depth of the problem.
Evidence-Grounded Citations
Pass 1 screens every RAG chunk for genuine relevance before it reaches the generation model. Only excerpts that directly support a specific, named factual claim about the ticket topic survive. The result is a note where every citation earns its place.
Key Modules

What's inside

  • Full ticket lifecycle: creation, triage, assignment, escalation, and closure
  • RBAC across five tiers — Admin, Tier 1 through Tier 4 — with scoped views and permissions
  • SLA tracking with colour-coded urgency indicators and breach threshold alerts
  • Ticket tags with AI-generated profiles: context, signals, actions, examples, and facets in structured JSON
  • Comment system with Markdown rendering, system-generated comments, and attachment linking
  • Attachment manager with gallery preview, password protection, bundle management, and per-file indexing status
  • Attachments chunked, embedded via ChromaDB client, and upserted with rich metadata (source name, ticket ID, attachment ID, chunk index)
  • Per-ticket chat sessions persisted in MySQL — users can switch, create, and delete sessions with full history
  • Five-model fallback chain with per-model retry logic and live countdown UI during rate-limit waits
  • Inline citation superscripts in chat responses; sources sidebar shows per-file indexing status
  • Ticket description and comments indexed alongside file attachments — every aspect of the ticket is queryable
  • Two-pass pipeline: Pass 1 screens citations, Pass 2 generates the note using only what survived screening
  • Three silent diagnostic frameworks shape tone and depth without appearing in the output
  • Structured format: INITIAL PROBLEM → Key Actions Taken → ADDITIONAL CONTEXT → Outcome or Open Questions
  • Citations appear as inline superscripts [N] with a collapsible source panel below the editor
  • Citations persisted to MySQL and re-rendered on every page load
  • Double-entry bookkeeping with Chart of Accounts and automatic journal entries on invoice and expense creation
  • Invoice management: create, edit, mark paid/unpaid, auto-post to ledger on status change
  • Expense tracking with category assignment, supplier info, and ledger integration
  • Budget module: targets per account category, actuals tracked in real time
  • SVG-based analytics dashboard — revenue vs expenses, budget utilisation gauges, ledger balance summaries, no external charting libraries
  • Structured article management with rich text editing, categorisation, and tagging
  • AI-assisted tag profiling: context, signals, recommended actions, examples, synonyms, and facets generated on demand
  • Articles surfaceable during ticket handling to give agents contextual self-service material
  • Admin interface showing total chunk count, indexed sources grouped by ticket and attachment
  • Filter by ticket ID, delete chunks per attachment, or wipe all indexed content for a ticket
  • Test Query panel: run a live semantic query against ChromaDB and inspect retrieved chunks with distance scores
  • Start ChromaDB button: bring the vector store online from within the app, with live status indicator and auto-reload
